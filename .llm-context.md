# draw.wine — LLM Context Map

A real-time collaborative whiteboard application. This file provides comprehensive context for working with multiple LLMs on this codebase.

---

## 🏗️ Project Overview

**draw.wine** is a monorepo containing a React-based frontend and an Express-based backend, enabling real-time collaborative drawing with AI-assisted generation.

### Key Features

- Real-time multiplayer drawing over Socket.IO
- Room-based collaboration with live cursor sync
- Drawing tools: select, pencil, text, shapes (rect, circle, diamond, line, arrow), eraser, laser
- Sketch-style rendering via Rough.js
- Gemini-powered AI drawing generation (vector & raster modes)
- PWA-enabled frontend
- Email-based room invitations

### Repository Info

- **Repo:** `pandarudra/draw.wine`
- **Default Branch:** `main`
- **Current Branch:** `preview`
- **Languages:** TypeScript (primary), React, Express
- **Monorepo Layout:** `be/` (backend), `fe/` (frontend), `docs/` (docs)

## 🔄 Key Data Flows

### 1. **Drawing Synchronization**

```
User Draw Event (Canvas)
  → DrawingContext dispatch
  → useCanvasBoardState hook
  → CollabContext emit socket event
  → Backend: socket.event.ts handler
  → Broadcast to all peers in room
  → Peers update DrawingContext
  → Rerenders update canvas
```

### 2. **Real-time Collaboration**

```
Room Creation/Join
  → CollabContext.tsx establishes Socket.IO connection
  → Backend: CollabDrawingServer tracks sessions
  → Peers join same room namespace
  → Live cursor positions broadcast
  → Elements synced via `draw`, `erase`, `transform` events
```

### 3. **AI Generation Flow**

```
User requests AI generation
  → fe/components/ai/ collection → aiApi.ts helper
  → POST /api/ai/generate → be/controllers/ai.controller.ts
  → be/services/ai.service.ts calls Gemini API
  → Returns SVG/raster → frontend renders via normalizeAiLayout.h.ts
  → User can accept/reject/edit
```

### 4. **Export Pipeline**

```
User clicks Export
  → useExportModal hook
  → ExportModal.tsx displays format chooser
  → export.h.ts serializes canvas
  → Download via blob URL (PNG/JPG/SVG/JSON)
```

## 🎯 Key Concepts & Patterns

### 1. **Element Type System**

All drawable elements inherit from base `Element` interface:

- **Type:** `'draw' | 'text' | 'rect' | 'circle' | 'diamond' | 'line' | 'arrow' | 'laser'`
- **Position:** `(x, y)`
- **Dimensions:** `width, height`
- **Styling:** `strokeColor, strokeWidth, fillColor, textContent`
- **Transform:** `rotation, isFlipped`

**Location:** `fe/src/types/element.ts`

### 2. **Drawing Context Structure**

Manages active tool, stroke properties, and fill color globally:

```typescript
{
  activeTool: 'draw' | 'select' | 'pencil' | ...
  strokeColor: string
  strokeWidth: number
  fillColor: string
  isFilledRect: boolean
  isRoughEdges: boolean
  // ... more properties
}
```

**Location:** `fe/src/contexts/drawing/DrawingContext.tsx`

### 3. **Collaboration Context**

Manages Socket.IO connection and room state:

```typescript
{
  socket: Socket | null
  roomId: string | null
  peers: Map<socketId, PeerInfo>
  isConnected: boolean
  messages: CollabMessage[]
  // ... more properties
}
```

**Location:** `fe/src/contexts/collab/CollabContext.tsx`

### 4. **Canvas Board State Hook**

Core hook for canvas data and operations:

```typescript
useCanvasBoardState() → {
  elements: Element[]
  selectedElementIds: Set<string>
  addElement(element): void
  removeElement(id): void
  updateElement(id, props): void
  undo(): void
  redo(): void
  selectElements(ids): void
  // ... more methods
}
```

**Location:** `fe/src/hooks/useCanvasBoardState.ts`

### 5. **Socket.IO Event Patterns**

Backend emits/listens to standardized events:

- `draw` → payload: `{ elementId, x, y, tools }`
- `erase` → payload: `{ elementIds: string[] }`
- `transform` → payload: `{ elementId, transform }`
- `cursor` → payload: `{ x, y, userId }`
- `room:join` → triggers broadcast to peers
- `room:leave` → cleanup session

**Location:** `be/src/events/socket.event.ts`

### 6. **API Route Structure**

#### Rooms API (`be/src/routes/rooms.routes.ts`)

- `GET /api/rooms/:roomId` — Fetch room state
- `POST /api/rooms` — Create new room
- `POST /api/rooms/:roomId/invite` — Send invite email
- `GET /api/rooms/:roomId/status` — Check connection health

#### AI API (`be/src/routes/ai.routes.ts`)

- `POST /api/ai/generate` — Request drawing generation
- Request payload:
  ```json
  {
    "prompt": "...",
    "mode": "vector" | "raster",
    "width": number,
    "height": number
  }
  ```
- Response: SVG string or base64 image

## 💾 State Management

### Frontend

- **Contexts:** DrawingContext, CollabContext, ThemeContext, GeneralContext, AiContext
- **Hooks:** useCanvasBoardState (main canvas state + undo/redo)
- **localStorage:** Canvas saved via `storeProgress.h.ts`
- **No Redux/Zustand:** Context + hooks sufficient

### Backend

- **In-Memory:** CollabDrawingServer singleton stores active rooms/peers
- **Session Manager:** `sessionManager.ts` tracks user sessions
- **No Database:** Currently stateless (add DB if persistence needed)

## ⚡ Performance Considerations

1. **Canvas Rendering:** Rough.js can be slow on large element counts; use `viewport.h.ts` culling
2. **Socket Events:** Batch element updates to prevent message flooding
3. **Memory:** CollabDrawingServer stores all peer data in-memory; add cleanup for stale sessions
4. **Images:** Cached via `imageLoader.h.ts` to prevent repeated fetches
5. **localStorage:** Limited to 5–10MB; compress or paginate large canvases
